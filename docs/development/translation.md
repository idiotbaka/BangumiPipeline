# LLM 翻译

本文按需读取；代码路径相对仓库根目录。修改相关行为时同步更新本文。

设置保存到 `llm_settings`：

- `base_url`：OpenAI Chat 兼容接口 v1 根地址。
- `api_key`：Bearer token，可为空以兼容本地模型。
- `model`：模型名称。
- `timeout_seconds`：单次请求总超时，默认 60 秒，可配置为 1～3600 秒的整数；管理 API 字段为 `timeoutSeconds`。旧客户端省略字段或传 0 时沿用默认 60 秒，不表示无限等待。
- 测试连接要求模型只返回 `OK`。

任务行为：

- 遍历原文非空且中文字段为空的元数据字段。
- 翻译目标包括番剧标题、番剧简介、分集标题、分集简介、角色简介、声优简介。
- 如果原文本身是中文且不需要清理，则直接复制到中文字段。
- 包含日文假名时必须走 LLM。
- 剧情简介和分集简介要清理脚本、演出、作画、制作人员等非剧情信息。
- LLM 请求串行，使用系统网络代理；翻译与连接测试共用配置的单次请求超时，覆盖连接、等待响应和读取响应体。已有任务在每轮开始读取配置，保存新设置后从下一轮生效；连接测试使用表单当前值。
- 任一字段翻译失败会结束本轮，失败字段仍保持中文为空；下一轮按固定顺序重新选取，可能持续重试同一个失败项并阻塞其后的条目。优先级依次为番剧标题、番剧简介、分集标题、分集简介、角色简介、声优简介；某个声优失败不会阻止下一轮先处理新出现的更高优先级字段。Scheduler 会释放运行状态，属于失败项阻塞后续进度，而非任务锁永久占用。延长超时可以缓解慢响应导致的失败，不会跳过始终失败的条目。
- 翻译及保存错误包含番剧名称、Bangumi ID、内容类别，分集另含类型/话数/标题及 episode ID，角色和声优另含名称及 Bangumi ID；保留原始 API 错误，不按 HTTP 400 自动跳过。声优全局共享，错误选择一个未删除的关联番剧作定位；已无关联时显示全局资料及声优信息。
- 自动保存以稳定 Bangumi ID 定位，同时要求原文仍与请求时相同且中文仍为空；元数据刷新或人工编辑导致条件不再成立时丢弃旧结果并继续选取目标，避免慢请求覆盖人工译文。仅实际写入的结果计入完成日志和汇总。
- 不记录 API KEY。
- 翻译成功日志可以记录原文和译文用于调试。

提示词约定：

- 直接输出结果，不输出说明、引号或 Markdown 代码块。
- 保留或优化段落格式。
- 角色名或专有名词首次出现用括号标注原文。
- 双引号统一使用中文直角引号 `「」`。

## 管理端进度

- `/translations` 每行一部未软删除的番剧；`GET /api/translation/anime` 支持 `q` 标题/别名搜索、`status` 筛选、`page` 和 `pageSize`，先筛选后分页。
- 六类进度与任务选取条件一致：有原文才计入总数，对应中文字段非空计为完成。上游自带中文、中文直拷、LLM 译文都计为完成，无法根据现有字段区分来源；无原文单独计数，不计入待翻译。
- 分集包含所有当前入库类型；角色按当前入库范围统计。声优通过 `character_actors` 按每部番剧的 `actor_id` 去重，中文结果仍全局共享。
- 状态按顺序派生：有待翻译字段为 `pending`；无待翻译但详情/角色/分集任一抓取阶段未完成为 `metadata_pending`；全部阶段完成且无可处理原文为 `no_content`；其余为 `completed`。抓取未完成或失败另显示提示，不能把尚未抓到的资料视作翻译完成。
- 展开行按需调用 `GET /api/translation/anime/{bangumiID}`，展示各项目的 `completed` / `pending` / `no_source`，支持按类别和明细状态筛选；列表仍只返回轻量明细，编辑时单独读取原文和译文。
- 页面展示对应计划任务启用情况、最近运行状态及错误，手动刷新。翻译错误没有逐字段持久状态，任务遇错结束本轮，失败项仍是待翻译；不提供逐番剧“翻译失败”或“正在翻译”判断，也不把通用 `updated_at` 当作翻译完成时间。
- 进度针对当前入库内容；新增资料或原文变化导致中文字段清空后，列表自然恢复为待翻译。不提供自动跳过、清空译文或从页面调用 LLM 的操作。

## 人工编辑译文

- 明细状态列后提供“编辑翻译”，待翻译和已完成均可编辑，无原文禁用。弹窗原文只读，中文译文为 textarea，保存时去除两端空白并拒绝空白内容。
- 管理员 `GET/PUT /api/translation/anime/{bangumiID}/targets/{kind}/{targetID}` 按六类 kind 和公开 Bangumi ID 定位项目。分集/角色 ID 是 `episode_id` / `character_id`，不是重建后会变化的本地行 ID。服务端验证项目属于该未软删除番剧；声优通过 `character_actors` 验证关联，不能用其他番剧的 ID 越界编辑。
- GET 返回 `item`，含轻量明细字段及 `originalText`、`translatedText`、`shared`。PUT 必须提供 `originalText`、`expectedTranslatedText` 和 `translatedText`，前两项是打开表单时的原始值，不能省略；在单次 Writer UPDATE 中同时比较两项及当前归属，内容变动返回 `409 translation_conflict`，不会覆盖新内容。
- 保存直接更新既有中文字段，不新增 schema 或额外完成状态；对应项目随即计为已完成，下一轮自动任务不再选择该项。所有展开明细和当前筛选列表重新读取，包括受共享声优影响的番剧及更新后的分页。
- 声优中文简介全局共用，弹窗明确提示修改会影响所有关联番剧。人工保存日志记录类别、番剧及目标 ID，不额外记录表单正文。
- 人工译文与现有译文遵循相同刷新规则：原文未变化时保留，原文变化时清空；不保证覆盖上游自带中文的刷新行为。人工保存不会清除计划任务历史错误，运行状态在下一轮执行后更新。
